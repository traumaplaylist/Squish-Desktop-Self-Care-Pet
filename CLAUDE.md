# CLAUDE.md — правила проекта Squish

> **Squish — Desktop Self-Care Pet.** Desktop-приложение для Windows: питомец-компаньон в стиле Finch + умные перерывы в стиле LookAway + маленькие задачи с наградами.
> Полное ТЗ: `docs/SPEC.md`. Журнал прогресса: `PROGRESS.md`. Читай оба в начале КАЖДОЙ сессии.

## Стек (не менять без явного согласия владельца)
- Electron (последняя стабильная) + electron-vite + React 18 + TypeScript (strict)
- Стили: CSS Modules или plain CSS. Никаких UI-китов типа MUI — интерфейс маленький и кастомный.
- Тесты: Vitest для всей логики ядра.
- Сборка: electron-builder, таргет Windows NSIS (x64).
- Нативные вызовы Windows: `koffi` (FFI без компиляции). НЕ использовать пакеты, требующие node-gyp / Visual Studio Build Tools.
- Хранение: свой модуль на JSON с атомарной записью (write tmp → rename). Без SQLite и без electron-store.
- Сеть: приложение НЕ ходит в интернет. Никакой телеметрии, аналитики, автообновлений в MVP.

## Архитектура (строго)
```
src/
  core/          ← ЧИСТАЯ логика, без Electron, без Node API, без Date.now()
    clock.ts       интерфейс Clock (now()), FakeClock для тестов
    scheduler.ts   расписание перерывов (state machine)
    pet.ts         потребности, настроение, энергия, рост, серии
    water.ts       учёт воды
    rewards.ts     энергия, монеты, приключения
    events.ts      типы событий (единый лог)
    types.ts
  main/          ← Electron main process
    index.ts       bootstrap, single-instance lock
    windows/       widget, overlay (на каждый монитор), stats, settings, onboarding
    tray.ts
    hotkeys.ts
    smartPause/    fullscreen.ts (koffi), mic.ts (реестр), idle.ts, foregroundApp.ts
    storage.ts     атомарный JSON
    ipc.ts         типизированные IPC-каналы
    engine.ts      склейка core + таймер tick раз в 1 с
  preload/       contextBridge, только типизированный API
  renderer/
    widget/  overlay/  stats/  settings/  onboarding/
    pet/
      PetRenderer.ts        интерфейс
      SvgBlobRenderer.tsx   реализация v1
      (позже) SpriteSheetRenderer.tsx
    i18n/ ru.json en.json
```
- `core/` тестируется без Electron. Всё время — только через `Clock`. Никаких `setTimeout` внутри core: main вызывает `engine.tick(now)` раз в секунду.
- Renderer никогда не меняет состояние напрямую — только шлёт команды через IPC, main — единственный источник истины, рассылает снапшот состояния.
- Питомец рисуется ТОЛЬКО через интерфейс `PetRenderer`. Остальной UI не знает, SVG это, спрайты или 3D.

## Безопасность Electron
- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true` для всех окон.
- Preload отдаёт минимальный типизированный API, не сырой `ipcRenderer`.
- CSP в html: `default-src 'self'`.

## Продуктовые принципы (из отзывов пользователей, см. SPEC раздел 0)
- Задачи и перерывы всегда важнее магазина и косметики — в UI и в порядке работы.
- Никогда не ставить галочку за пользователя. Никогда не наказывать: без смертей питомца, штрафов, отъёма валюты, «просрочено».
- Никаких ивентов, ограниченных по времени предметов, квестов-обязательств, пушей «вернись».
- Не прерывать: умная пауза и «естественный момент» — P0, а не полировка.
- Скорость ввода задачи и отклик галочки — измеряемые требования (SPEC 6).
- Приоритеты в SPEC: [P0] / [P1] / [P2]. Не укладываешься — режь P2, потом P1. P0 не режется.

## Правила работы
1. Перед кодом — короткий план (5–10 пунктов) по задаче дня. Потом выполняешь.
2. Маленькие коммиты с понятными сообщениями (`feat(scheduler): ...`, `fix(widget): ...`).
3. После каждого блока: `npm run typecheck && npm test`. Красное — чинишь, не идёшь дальше.
4. Новая зависимость — только если без неё больше 50 строк кода. Пиши в PROGRESS.md, зачем добавил.
5. Всё, что нельзя проверить без Windows-GUI, помечай в PROGRESS.md в разделе «Проверить руками» с точными шагами.
6. Не выдумывай API. Если не уверен в Windows/Electron API — пиши обёртку с fallback (функция возвращает `unknown`, приложение работает дальше) и отмечай в PROGRESS.md.
7. В конце сессии ОБЯЗАТЕЛЬНО обнови PROGRESS.md: что сделано, что не доделано, известные баги, следующий шаг. Это хэнд-офф — следующую сессию может продолжить другой агент без контекста.
8. Тексты интерфейса — только через i18n-ключи. Основной язык — русский, второй — английский.
9. Не делать медицинских утверждений в интерфейсе («лечит», «предотвращает болезни»). Формулировки — «забота о себе», «отдых для глаз». В «О программе» — строка «не является медицинским продуктом».

## Режим отладки
- `SQUISH_DEBUG=1` → ускорение времени ×60 (20 минут = 20 секунд), окно Debug с кнопками: «перерыв сейчас», «+1 день», «стадия роста +1», «сбросить состояние», «выпить воду», «симулировать фуллскрин/микрофон».
- Ускорение реализуется подменой Clock, а не правкой таймингов в коде.

## Команды
- `npm run dev` — запуск в режиме разработки
- `npm run dev:debug` — то же с SQUISH_DEBUG=1
- `npm test` / `npm run test:watch`
- `npm run typecheck`
- `npm run build:win` — установщик NSIS в `dist/`
